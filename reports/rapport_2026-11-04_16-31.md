## 🛑 2. Filtre Anti-Coût (Critique)
Alerte rouge. Une erreur 503 (Service Unavailable / Surcharge), c'est **le piège à fric numéro un** dans le monde du dev. Si on ne verrouille pas ça immédiatement, le réflexe paresseux va être de sortir la carte bancaire. 

Voici l'autopsie des **coûts cachés mortels** qui guettent ce problème :

---

### 1. Le piège de la facilité : "On va juste upgrader le serveur"
* **Le risque :** Le développeur moyen va te dire : *"C'est saturé, passons du plan gratuit au plan à 5$, 10$ ou 20$/mois sur Render/Vercel/Railway/VPS"*.
* **Le verdict : DÉTRUIT. C'est 0 dirham, pas un centime.** Si le code ne tient pas sur les quotas gratuits, c'est que le code ou l'architecture est mal foutu(e). On ne masque pas de l'incompétence d'optimisation avec de l'argent.

### 2. L'illusion du cache et des bases managées payantes
* **Le risque :** Vouloir ajouter un Redis managé payant (Upstash au-delà du quota, Redis Cloud payant) ou upgrader la base de données (Supabase Pro, Neon scale-up) pour encaisser les requêtes concurrentes.
* **Le verdict : DÉTRUIT.** Aucun service managé payant ne franchira cette porte.

### 3. Les outils de monitoring et logs (APM)
* **Le risque :** Installer Datadog, New Relic ou un Sentry payant pour "diagnostiquer la surcharge". 
* **Le verdict : HORS DE QUESTION.** Les logs console natifs et les métriques de base suffisent largement. On ne paie pas pour regarder un serveur planter.

### 4. Le piège des requêtes en boucle (Retry Hell)
* **Le risque caché vicieux :** "6 tentatives". Si le client boucle sans *exponential backoff* ou surcharge une API externe qui facture au volume (ex: OpenAI, Google Maps, Twilio), la facture va exploser en arrière-plan pendant que le serveur est à genoux.
* **Le verdict : DANGEREUX.** Si une API payante est appelée dans cette boucle, le projet est financièrement mort.

---

### LA SEULE DIRECTIVE TOLÉRÉE : 0 DIRHAM STRICT

Si ce problème doit être résolu, ce sera **uniquement par de l'ingénierie brute à coût zéro** :

1. **Bride radicale (Rate Limiting local) :** Si les serveurs saturent, on bloque agressivement les abus côté client ou via des règles gratuites (Cloudflare Free Tier uniquement).
2. **Décharge sur le client (Browser Compute) :** Déplacer les calculs lourds du serveur vers le navigateur de l'utilisateur. Coût serveur : 0.
3. **Mise en cache statique agressive :** Servir du HTML/JSON pré-généré au lieu de requêter la base à chaque clic.
4. **Kill des requêtes inutiles :** Arrêter le polling sauvage, optimiser les index de requêtes SQL (qui bouffent 100% du CPU gratuit).

**Conclusion :** Tout correctif qui propose d'appuyer sur un bouton "Upgrade" ou d'ajouter un service tiers payant est **rejeté et brûlé**. Tu résous ça avec du code, du cache gratuit et du bon sens, ou ça ne se résout pas. 0 DH.
